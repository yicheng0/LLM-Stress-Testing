# 缓存专项可配置样本量 Checklist

> 每项均通过运行代码或观察行为验证；全部通过后才能宣告功能完成。

## 配置与请求规模

- [ ] AC1：配置页显示“公共前缀 Token”和“每个 Case 请求次数”，默认分别为 4096 和 10。（验证：首次打开缓存专项配置页，期望两个数字输入框显示默认值）
- [ ] AC1：公共前缀 Token 必须为正整数。（验证：分别输入 0、负数和有效正整数，期望无效值不能提交，有效值可以提交）
- [ ] AC1：每个 Case 请求次数只允许 2 到 100。（验证：分别提交 1、2、100、101，期望只有 2 和 100 通过）
- [ ] AC2：计划请求总数等于选中 Case 数乘以每 Case 请求次数。（验证：选择 3 个 Case、请求次数为 10，期望页面显示 30；取消 1 个 Case 后显示 20）
- [ ] AC2：计划请求总数不包含失败重试。（验证：配置每 Case 4 次并模拟一次请求内部重试，期望进度和 Summary 计划数仍为每 Case 4）
- [ ] N2：配置页不出现并发、矩阵、持续时间或请求间隔配置。（验证：检查页面，期望只新增 Token 长度和串行请求次数）

## 公共前缀与请求关系

- [ ] N3：公共前缀按照用户目标 Token 生成并同时记录目标值与实际估算值。（验证：分别配置 1024 和 8192，期望 Summary 中目标值准确、实际值达到对应范围）
- [ ] N3：逐请求实际输入 Token 优先展示上游 usage，不用目标前缀 Token 冒充。（验证：模拟上游返回不同输入 Token，期望明细显示上游数值）
- [ ] AC3：每个 Case 第 1 次请求标记为“缓存建立”，第 2 次及以后标记为“缓存验证”。（验证：每 Case 运行 4 次，期望阶段依次为建立、验证、验证、验证）
- [ ] AC3：缓存建立请求不产生命中、未命中或无法判定分类，也不进入命中率。（验证：让建立请求返回缓存字段，期望分类仍为空且分母不增加）
- [ ] F6：重复请求 Case 的全部请求消息关系相同。（验证：记录 4 次模拟请求体，期望消息序列完全一致）
- [ ] F6：尾部变化 Case 只在建立与验证之间改变尾部，所有验证请求保持相同公共前缀和验证尾部。（验证：记录 4 次请求，期望第 2 至 4 次相同且与第 1 次仅尾部不同）
- [ ] F6：多轮对话 Case 每次验证保留此前真实上下文并新增一轮。（验证：模拟返回不同回复，期望后续消息逐轮包含此前真实回复和新用户消息）
- [ ] N1：多轮真实回复仅在内存使用。（验证：对 Summary、Details、事件、HTML、Markdown 和 PDF 搜索唯一模拟回复，期望零命中）

## 串行执行、失败与停止

- [ ] AC2：选择 3 个 Case、每 Case 10 次时按 Case 顺序严格串行发送 30 个业务请求。（验证：模拟发送器记录开始和结束顺序，期望无请求重叠且调用数为 30）
- [ ] F5：同一 Case 的下一次请求只在前一次请求完成后启动。（验证：模拟慢响应并记录时间，期望任意两个业务请求没有并发区间）
- [ ] F5：缓存建立失败时不再发送当前 Case 的验证请求，但继续下一个 Case。（验证：让第一个 Case 的第 1 次失败，期望该 Case 只有 1 次调用，后续 Case 仍完整执行）
- [ ] F5：某次验证请求失败后继续当前 Case 的后续验证请求。（验证：让第 2 次验证失败，期望第 3 次及以后仍执行）
- [ ] AC7：运行页实时展示当前 Case、当前请求序号和已执行/计划请求数。（验证：运行慢速模拟任务，期望进度逐次从 0 更新至计划数）
- [ ] AC7：点击停止后不再发送新的业务请求或重试。（验证：在重试等待和 Case 中途分别停止，期望调用记录停止增长，任务进入取消终态）
- [ ] N6：部分完成任务仍保存已执行请求证据和准确计数。（验证：中途停止，期望 Summary 和 Details 只包含真实已执行请求）

## 单请求判定与命中率

- [ ] F7：验证请求明确返回大于零缓存命中 Token 时判定为“缓存命中”。（验证：模拟缓存命中字段，期望分类和计数为命中）
- [ ] F7：验证请求明确返回缓存字段且命中为零时判定为“未命中缓存”。（验证：模拟明确零值，期望不是无法判定）
- [ ] F7：验证请求成功但没有缓存字段时判定为“无法判定”。（验证：模拟普通 usage，期望不是未命中）
- [ ] F7：验证请求出现 HTTP、协议、超时或网络错误时判定为“执行失败”，并保留错误证据。（验证：分别模拟错误，期望状态码或错误类型进入明细）
- [ ] AC4：9 个验证请求为 6 命中、2 未命中、1 无法判定时，Case 命中率为 75.00%。（验证：运行聚合 fixture，期望分子 6、分母 8）
- [ ] AC5：所有验证请求均无法判定或失败时，Case 命中率显示“不可用”。（验证：构造分母为零，期望值为 null，页面/PDF 为“不可用”）
- [ ] AC6：总体命中率按所有 Case 的可判定验证请求合并计算。（验证：Case A 为 1/2、Case B 为 8/8，期望总体为 9/10，而不是两个百分比的平均）
- [ ] F9：无法判定和失败数量独立展示，不计入命中率分母。（验证：核对 Case 与总体计数之和及命中率公式）
- [ ] Case 汇总结论与请求证据一致。（验证：分别构造建立失败、全无法判定、部分命中和全未命中，期望汇总结论符合批准优先级）
