- [ ] AC1：直接刷新 `/tests/cache-diagnostics` 页面仍正常加载，不跳入普通测试表单。（验证：浏览器直接访问和刷新该地址，期望仍显示缓存专项配置页）
- [x] AC2：配置页默认选中“重复请求”“多轮对话”“尾部变化”三个 Case。（验证：首次打开页面，期望三张 Case 卡片全部处于选中状态）
- [ ] AC2：用户可以填写协议、接入域名、Endpoint、API Key、模型、最大输出 Token、超时和流式配置并启动任务。（验证：提交有效配置，期望创建成功并跳转 `/tests/cache-diagnostics/{task_id}`）
- [ ] AC2：未选择任何 Case 时不能提交。（验证：取消全部 Case 后点击启动，期望显示至少选择一个 Case 的校验提示且不产生任务）
- [ ] N2：页面不出现并发、测试时长、矩阵模式或自定义请求链配置。（验证：检查配置页，期望专项功能只提供连接、响应和内置 Case 参数）

## Case 请求关系与执行顺序

- [x] AC3：重复请求 Case 的准备请求与验证请求内容和消息结构完全一致。（验证：运行 Case 结构检查，期望两个请求描述相等）
- [x] AC3：多轮对话 Case 的验证请求完整保留准备阶段上下文并新增一轮消息。（验证：检查两个阶段的消息序列，期望验证序列以前者为前缀并增加后续消息）
- [x] AC3：尾部变化 Case 使用相同的 4096 Token 公共前缀，只改变短尾部内容。（验证：检查公共前缀摘要和两个阶段的尾部，期望公共前缀一致、尾部不同且实际公共前缀达到目标范围）
- [ ] F4：每个 Case 内始终先完成准备请求，再发送验证请求；两个阶段不并发。（验证：使用记录调用顺序的模拟发送器运行三个 Case，期望顺序为 `prepare -> validate`）
- [ ] F4：Case 按用户选择顺序逐个执行。（验证：提交非默认顺序的 Case ID，期望进度和 Summary 的 Case 顺序与提交顺序一致）
- [ ] N2：单次任务最多运行三个内置 Case。（验证：提交空列表、未知 ID 或超过限定范围的输入，期望接口拒绝；有效列表最多产生三组结果）

## 协议与缓存证据

- [ ] N3：OpenAI Chat/Responses、Anthropic Messages 和 Gemini 均能构造合法的专项请求。（验证：运行 payload 检查，期望协议字段、消息角色、输出限制和流式配置正确）
- [ ] N3：Anthropic 仅在稳定公共前缀内容块上添加 `ephemeral` 缓存控制。（验证：检查 Anthropic payload，期望稳定块带 `cache_control`，变化尾部和其他协议无该字段）
- [ ] N3：OpenAI 和 Gemini 请求不包含未声明的私有缓存参数。（验证：序列化 payload 后搜索缓存控制字段，期望不存在未知 `cache_control` 或 `prompt_cache` 参数）
- [ ] AC5：上游明确返回缓存字段且命中 Token 为零时，证据记录 `observed=true` 和零值。（验证：模拟包含缓存字段零值的 usage，期望结果不是“无法判定”）
- [ ] AC5：上游完全没有缓存字段时，证据记录 `observed=false`。（验证：模拟仅有普通 input/output usage，期望判定为“无法判定”）
- [ ] N3：现有 OpenAI、Anthropic、Gemini 和网关缓存字段别名均可识别。（验证：运行缓存解析回归，期望每种已支持字段得到正确命中/创建 Token 和 `observed=true`）

## 四类判定与失败隔离

- [x] AC4：验证请求成功且明确返回大于零的缓存命中 Token 时显示“缓存命中”。（验证：模拟命中响应，期望状态为 `cache_hit`，页面显示命中 Token 和命中率）
- [x] AC5：验证请求成功、缓存字段存在且命中为零时显示“未命中缓存”。（验证：模拟明确零命中响应，期望状态为 `cache_miss`）
- [x] AC5：验证请求成功但没有缓存字段时显示“无法判定”。（验证：模拟无缓存字段响应，期望状态为 `unverifiable`，不显示“测试失败”）
- [x] AC6：准备请求失败时显示“执行失败”和“准备阶段”，并且不发送该 Case 的验证请求。（验证：模拟准备阶段 HTTP 429，期望保留状态码、错误类型、错误信息且调用记录中没有该 Case 的验证请求）
- [ ] AC6：验证请求失败时显示“执行失败”和“验证阶段”。（验证：模拟验证阶段超时或 HTTP 错误，期望保留失败阶段及错误证据）
- [x] AC6：一个 Case 失败后其余 Case 继续执行。（验证：让第一个 Case 失败，期望后续 Case 仍产生完整结果）
- [ ] F6：判定不使用响应耗时或文本相似度。（验证：构造低延迟但无缓存字段的成功响应，期望仍为“无法判定”）
