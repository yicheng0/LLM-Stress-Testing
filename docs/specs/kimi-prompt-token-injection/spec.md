# Kimi Prompt Token 注入检测 Spec

## 背景

Kimi 能力测试集目前可以校验缓存、思考、JSON、stop、采样、工具调用和输出 Token，但无法发现供应商网关在转发请求时额外注入系统提示词或其他隐藏上下文。需要增加一个独立 Case，对比客户端可见请求内容与上游返回的输入 Token usage，给出可解释的注入风险结论。

## 目标

- 在 Kimi 测试集新增“Prompt Token 注入检测” Case。
- 使用请求内容的本地 Token 估算值与上游 usage 进行对比。
- 区分通过、疑似注入、无法判定和请求失败，不把缺失 usage 误判为通过。
- 在实时结果表、Case 详情和最终报告中保留判定证据。

## 功能需求

- F1: 默认测试集包含“Prompt Token 注入检测” Case，用户可以像其他 Case 一样单独选择或取消选择。
- F2: Case 发起请求时使用固定、可审计的测试提示词，并记录脱敏后的请求 Token 估算值与估算方法。
- F3: 当上游返回输入 Token usage 时，系统将其与本地估算值按可配置容差进行比较；在容差内显示“通过”，明显超出容差显示“疑似提示词注入”。
- F4: 当上游缺少输入 Token usage、本地 Token 估算不可用或协议不提供可比字段时，显示“无法判定”或“接口不支持”，不得显示“通过”。
- F5: 请求发生 HTTP、协议或网络错误时，显示“请求失败”，并保留脱敏错误类型和错误信息。
- F6: 结果页面实时展示该 Case 的运行状态、耗时、输入 Token 估算值、上游 usage、差值/比例和最终判定；详情抽屉展示判定证据。
- F7: 结果文件只保存脱敏后的请求摘要、Token 数值、判定规则和响应片段，不保存 API Key、完整 Prompt 或完整响应。

## 非功能需求

- N1: 不改变现有 9 个 Kimi Case 的请求参数、判定逻辑和结果格式兼容性。
- N2: 不使用延迟、文本相似度或模型回答内容推断提示词注入。
- N3: OpenAI-compatible、Anthropic、Gemini 协议按照各自 usage 字段能力执行；不支持输入 Token 对比的协议明确标记为“接口不支持”。
- N4: 使用本地可控模拟响应覆盖通过、疑似注入、usage 缺失和请求失败场景，不使用真实 API Key 做回归。

## 不做的事

- 不尝试还原或展示供应商注入的完整隐藏提示词内容。
- 不将单次 Token 偏差直接作为整个测试任务的系统错误或自动封禁供应商。
- 不在本 Case 中检测输出内容里的越权指令、数据泄露或模型安全性。
- 不改变现有缓存专项测试和普通压测接口。

## 验收标准

- AC1: Kimi 测试集 Case 列表显示第 10 个“Prompt Token 注入检测”，默认选中，且可单独选择执行。
- AC2: 本地模拟接口返回输入 Token 在容差内时，该 Case 显示“通过”，并展示本地估算值、上游 usage 和差值。
- AC3: 本地模拟接口返回输入 Token 明显超出容差时，该 Case 显示“疑似提示词注入”，并展示超出数值和比例。
- AC4: 缺少输入 Token usage 或协议不支持可比字段时，该 Case 显示“无法判定”或“接口不支持”，不能显示“通过”。
- AC5: HTTP 或网络错误时，该 Case 显示“请求失败”，详情中能看到脱敏错误信息。
- AC6: 结果页实时表格和右侧详情抽屉能看到该 Case 的状态、耗时、Token 证据和判定说明。
- AC7: 生成的 summary、details 和报告中不包含 API Key、完整 Prompt、完整请求体或完整响应体。
- AC8: Kimi 专项回归测试与前端生产构建通过，已有 9 个 Case 的测试断言不回归。
