# PDF 请求明细完整化 Checklist

> 每项均通过运行代码或观察最终 PDF 验证。

## 实现完整性

- [x] 单次测试 PDF 包含“请求状态、延迟与 Token”表（验证：导出示例 PDF，期望看到 ID、结果、状态码、总延迟、TTFT、输入 Token、输出 Token、总 Token、TPS）。
- [x] 单次测试 PDF 包含“请求缓存与错误”表（验证：导出示例 PDF，期望看到 ID、缓存命中 Token、缓存创建 Token、含缓存 Token、缓存命中率、错误类型、错误信息）。
- [x] 两张表展示相同顺序的全部成功和失败请求（验证：使用固定 ID 的成功与失败样本，期望两个 ID 均在两张表中出现）。
- [x] 成功请求显示 `OK`、实际状态码和 Token/缓存数据（验证：检查成功样本行，期望结果为 `OK`、状态码为 `200`、数值与输入详情一致）。
- [x] 成功请求的错误类型和错误信息显示“-”（验证：检查成功样本的缓存与错误行）。
- [x] 失败请求显示 `FAIL`、实际状态码、错误类型和错误信息（验证：检查失败样本行，期望 ID、状态码和错误内容一致）。
- [x] 失败样本聚合摘要继续存在（验证：PDF 文本中包含失败数量、状态码、错误类型和请求编号）。

## 缺失值与边界

- [x] 缺失 TTFT 显示“不可用”（验证：构造 `ttft_sec=None` 的请求并导出 PDF）。
- [x] TTFT 为真实零值时显示 `0.0000s`（验证：构造 `ttft_sec=0` 的请求并导出 PDF）。
- [x] Decode 为零或 TTFT 缺失导致 TPS 无法计算时显示“不可用”（验证：构造零 Decode 和缺失 TTFT 样本）。
- [x] 历史详情缺少新增字段时不报错、不推算，字段显示“不可用”（验证：使用缺少缓存字段的字典形式详情渲染 PDF）。
- [x] 长错误信息在单元格内换行且不越出页面（验证：使用长错误文本生成并检查 PNG）。

## 集成

- [x] PDF 下载路径与响应结构保持不变（验证：检查现有下载接口未发生签名或路径变化）。
- [x] 已存在旧 PDF 时重新生成并原子替换（验证：运行现有原子替换测试，期望旧内容被新内容替换且临时文件清理）。
- [x] PDF 仍包含原有汇总指标、延迟分布、图表、状态码与错误分布（验证：运行现有 PDF HTML 测试）。
- [x] 矩阵 PDF 行为保持不变（验证：运行现有矩阵 PDF 测试）。

## 编译与测试

- [x] PDF 模块语法检查无错误（验证：`python -m py_compile backend/app/core/pdf_report.py`）。
- [x] Python 回归测试通过（验证：`PYTHONPATH=. <项目虚拟环境>/bin/python -m unittest tests.test_core_refactors -q`，期望零失败、零错误）。
- [x] Git 差异无空白错误（验证：`git diff --check`，期望无输出）。

## 端到端场景

- [x] 导出包含成功和失败请求的单次测试 PDF，最终文件能看到全部 15 类请求字段（验证：使用 `pdftotext -layout` 搜索表头和代表性数据）。
- [x] 导出足够多请求形成多页明细，分页后表头仍清晰（验证：使用 `pdfinfo` 确认多页，并逐页检查 `pdftoppm` 生成的 PNG）。
- [x] 多页 PDF 无横向截断、文字重叠、不可读列或错误信息溢出（验证：逐页视觉检查 PNG）。
- [x] 对已存在 PDF 的历史任务再次下载，文件重新生成并展示详情中现有的新版字段（验证：先生成旧文件，再触发生成并进行 PDF 文本提取对比）。

## 范围检查

- [x] 未修改数据库结构、压测采集算法、网页请求明细和下载 API。
- [x] 未提交请求/响应正文、API Key、生成的 PDF/PNG 或结果数据。
- [x] 未把 `frontend/node_modules`、pnpm 文件及其他既有无关工作区改动纳入本次实现。
